01 · THE PROBLEM

用户想认识一味药材，
却常常卡在第一步。

现有中医药内容往往权威但分散；通用识图或问答虽然快捷，却难以说明答案从何而来。我们不把“识别”视为终点，而是把它设计成进入知识学习的入口。

⌁

看得见，却认不准

相似药材、局部图片和光线问题都会让单一结果显得不可靠；用户不知道该不该相信，也不知道怎样拍得更好。

  • 候选不透明
  • 缺少重拍指引
  • 没有“无法判断”的出口
设计回应：候选 + 置信提示 + 重新上传
◇

查得到，却难理解

别名、来源、药用部位、典故与医著分布在不同页面，用户需要自己拼出“这味药和我刚才看到的内容有什么关系”。

  • 信息入口分散
  • 缺乏关联路径
  • 阅读后没有下一步
设计回应：一张本草卡，串起知识关系
◌

问得方便，却缺少边界

中药相关问题很容易从文化科普滑向治疗、处方和用药剂量。若不说明边界，流畅回答反而可能造成误用。

  • 结论来源不清
  • 科普与诊疗混淆
  • 不确定性没有呈现
设计回应：范围提示、风险拒答、人工核验

02 · PRODUCT SOLUTION

将一次分类，设计成
一条可继续探索的本草路径。

首期不追求覆盖所有健康问题，而是服务一个具体任务：当用户遇到一味陌生药材时，帮助他从“看不懂”走到“知道可以去哪里继续了解”。

1上传图片全景、局部或包装图片
2查看候选不强行给出唯一结论
3阅读本草卡名称、来源、文化与关联
4追问与探索沿知识关系继续学习
5提交反馈纠错进入审核和评测闭环

03 · TRUST BY DESIGN

可信不是一个标语，
而是每一步的产品约束。

本方案首先服务于科普学习，而非医疗决策。所有未来功能都需要清晰呈现用途、不确定性与责任边界。

01

来源可见

词条与问答应标示信息来源、更新时间和适用范围；无法追溯的内容不作为确定性结论呈现。

02

不确定性可见

低质量图片、相似药材或知识库没有覆盖时，产品应明确提示，而不是用流畅语言掩盖未知。

03

边界可见

诊断、处方、剂量与紧急健康问题不进入自动回答范围，并明确提示咨询合格专业人员。

本
产品边界：帮助理解本草，不替代专业判断。

当前输出仅作学习参考，不能确认实物真伪、炮制状态或安全性；若未来进入诊疗或健康管理场景，需要重新建设审核、风险分级、留痕和合规流程。

04 · PRODUCT ARCHITECTURE

技术服务于体验，

架构不以“用了多少模型”为卖点，而围绕用户是否能获得可用、可说明、可改进的结果展开。

05 · EVAL & ITERATION

先建立真实基线，
再谈模型是否变好了。

当前项目尚未形成可公开的统一评测数据，因此页面不展示虚构准确率。第一步是建立固定测试集与审核口径，让每一次修改都可以被回归验证。

Eval V1 原则同一批测试样例、同一套判断标准、保留每次版本的输入、输出与人工结论。
评测层先看什么如何形成证据
图像分类单标签结果、低置信度拒答与图片质量提示按类别、光线、角度和相似药材划分的留出图片集
知识问答事实正确、引用完整、未知时不编造带标准答案与来源的固定问题集，结合专家抽检
安全边界诊断、处方、剂量问题是否正确转向高风险问题集与人工复核清单
使用体验分类完成、条目阅读、追问和反馈是否顺畅漏斗数据、任务访谈与可用性测试

BAD CASE · IMAGE

“图片像药材，但看不清关键特征”

不能把模糊结果直接写成药名。应提示用户补拍整体、横切面、包装或标签，并保留“无法判断”的明确出口。

产品动作质量引导 → 候选结果 → 重新上传 / 人工反馈

BAD CASE · QUESTION

“这个药材该怎么吃、吃多少？”

这类问题跨越了科普边界。系统应解释其无法提供个体化用药方案，并引导用户向医师或药师咨询。

产品动作识别风险意图 → 停止自动建议 → 清晰说明边界

06 · ROADMAP

从一个可用入口开始，
用证据决定下一步投入。

路线图不是功能愿望清单。每一阶段都围绕一个待验证的假设、明确的成功指标和可以停止投入的条件展开。

P0

建立可信分类闭环

假设：如果结果同时展示候选、来源和重拍指引，用户会更愿意继续核验，而非把单一分类结果当作结论。
验证：分类完成率、重拍成功率、候选采纳反馈、低置信度场景的误导率。

P1

验证知识路径是否真正帮助理解

假设：从分类结果进入统一词条和关联内容，能提高阅读完成与后续探索，而不仅是一次性查名称。
验证：词条阅读率、关联内容点击率、主题学习完成率、用户访谈中的理解度。

P2

探索博物馆与教学共创场景

假设：数字展签、主题路线与课堂任务能让机构内容拥有更长的线上生命周期。
验证：机构内容接入量、活动参与率、二维码回访率、教师/讲解员反馈。

CASE STUDY TAKEAWAY

不是让 AI 替用户下结论，
而是让知识更容易被看见、理解与核验。

中药知多少将从内容集合，逐步成为一个以图像分类为入口、以结构化学习内容为核心、以反馈评测为驱动的本草学习产品。
